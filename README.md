# 公文格式排版

把内容或现有的 Word 文档，排成符合 **GB/T 9704-2012《党政机关公文格式》** 国家标准的公文。

支持通知、请示、报告、函、纪要等党政机关公文。重排不改文字：你说什么，它就排什么。

---

## 一、先看这里：能做什么，不能做什么

用之前花一分钟看清边界，免得排完才发现不是想要的东西。

### 能做

- **原文一个字不增不减**：只调字体、字号、行距、缩进、对齐与分页控制，
  不补标点、不改编号、不新增页码（详见下一节）
- **从现有 Word 重排**：保留全部文字、编号、表格（含合并单元格），只换版式
- **从文本新建**：把一段话或一份提纲排成标准公文
- **检查编号层级**：核对「一、 →（一）→ 1. →（1）→ ①」是否跳层、跳号、用错括号
- **页码**：居中 / 奇偶页不同 / 不显示，三种都支持
- **保留分页控制**：「与下段同页」「段中不分页」「段前分页」跟着源文档走，标题不会掉在页末
- **字体自动回退**：本机没装国标字体时，自动挑最接近的等价字体，并明确告诉你替换了什么
- **排完自动验收**：逐条核对原文的文字、表格、图片有没有漏（见场景 7）

### 内容保真：一个字不增不减

排版只换版式，不动文字。具体来说：

| 不会做的事 | 例子 |
|---|---|
| 补标点 | 段落末尾缺句号，只提示，不替你补 |
| 改编号 | 源文档写「1.」就还是「1.」，不会统一成「1．」或反过来 |
| 新增页码 | 源文档没有页码就不加；要加需你明确说 |
| 补回自动编号 | 见下，默认保留原生编号，不并入正文文字 |
| 编造内容 | 主送机关、署名、成文日期、版记源文件没有就留空，不替你填 |

**关于 Word 自动编号**：「二、」这类序号有时不是手打的，而是 Word 自动生成的
（挂在 `w:numPr` 上）。源文件里它**不是字符**，渲染出来写进正文就等于给你加了字。
所以本技能**不把它写进正文**，而是把源文档的编号定义原样复制进成品、给段落带上
编号定位，**由 Word 自己渲染出「一、」「1.」等序号**——既不加字，也不丢可见编号，
层级与"章节内重新从 1 开始"等规则一并保留。
确实想固化成纯文字（以后不随列表自动更新），说一句"把自动编号转成文字"即可。

### 版头：原样保留，不重做

**源文件带红头和发文字号时，一律原样保留，不参与重排。** 红头是各单位的门面，替你重排等于改你的门面。

会自动识别文档开头的红头、发文字号、红色分隔线，整段原样搬到新文档——字体、颜色、字号、对齐、边框一概不变，只重排后面的正文。

| 红头形式 | 能否原样保留 |
|---------|------------|
| 文字红头（红色大字，如「××省教育厅文件」） | 能 |
| 图片红头 | 能，图片会一起带过去，不会变成空白或文档损坏 |
| 文本框红头 | 能，框内文字原样保留 |
| **用表格排的红头** | **不能**，按普通表格处理，会排到标题之后；此时会明确提示你，不会默默排错 |

红头与发文字号之间隔了空行也没关系，能一起识别（早期版本会在空行处停下，
把发文字号当成标题，已修）。**发文字号会按国标居中排布**（7.2.4）——源文件有没居中的，
照国标纠正，生成时会告诉你是哪一段。源文件没有版头时**不凭空生成**，那需要套用单位红头模板。

### 不做（这些要素本技能不生成）

| 不生成 | 说明 |
|--------|------|
| 红头、发文字号、分隔线 | **源文件有则原样保留**（见上）；源文件没有 / 从文本新建时不生成 |
| 签发人、份号、密级、紧急程度 | 国标 7.2 版头要素，本技能不处理 |
| 抄送机关 | 源文件有版记则随版记整块带走，没有不编造 |
| 印章位置、骑缝章 | 与用印流程绑定 |

**版记（印发机关 + 印发日期）源文件有就原样保留**：整块搬到文末，字号、印发机关与
印发日期之间的间隔、上下两条分隔线都不动，并沉到**最后一页版心最下方**（国标 7.4.2）。
不按正文重排，也绝不编造源文件里没有的抄送机关。

**正文里这些内容不保留**，但会明确提示你，不会一声不响地漏掉：
图片（位图）、矢量图形（分隔线这类线条/形状；**版记的分隔线例外**，随版记搬运）、
文本框、脚注、尾注、批注、修订标记、嵌入对象（图表 / OLE）、公式、
手动分页符（按 Ctrl+Enter 敲出来的那种）。

**页眉页脚文字是内容，不是"不保留"**：源文档页眉/页脚里的文字（如"内部资料，请勿外传"）
会参与验收，丢了就判不通过。只有脚注/尾注/批注、正文图片这些确实不处理的内容，
才归"部分完成／待确认"，交付时会单独说明。

**也就是说**：交付的是**从标题到版记的一整份**——版头（有则保留）、正文、落款、
版记都在；红头若源文件是图片形式、正文里的插图等，仍需自行补回。

### 适用前提

- **只适用于党政机关公文**。合同、协议、论文、商务文书、宣传材料不适用本格式。
- **输入必须是 `.docx`**。`.doc`、PDF、扫描件请先转成可编辑的 `.docx`，本技能不做格式转换。
- **只输出 `.docx`**，不生成 PDF，不生成图片版式。

## 二、用之前要准备什么

### 1. 字体（最关键的一项）

公文的字是"指定动作"：标题小标宋、正文仿宋、一级黑体、二级楷体、页码宋体。
**字体不随技能包分发**（字体受著作权保护，商用需自行取得授权），需要本机已安装。

- Windows 一般自带仿宋、楷体、黑体、宋体；`仿宋_GB2312`、`楷体_GB2312`、`方正小标宋简体` 多数需单独安装
- macOS 通常只有 `方正仿宋_GBK`、`楷体-简`、`黑体-简`
- Linux 多用 `FangSong`、`Kai`、`Hei`

本机缺哪个，脚本会按「国标名 → 等效字体 → 通用兜底」自动回退，并在生成时打印替换情况。**字号、行距、缩进、页边距不受影响，只有字形会变**——标题若回退到普通宋体，只是不够漂亮，不影响合规判定。

想提前知道本机情况，直接说：

> 检查一下这台机器能不能排公文，字体齐不齐

### 2. 内容要素

标题、主送机关、正文、附件、发文机关署名、成文日期。

**缺什么它会问你，绝不编造。** 单位名称、文号、金额、人名、日期这些一律以你给的为准，不会用占位内容糊弄。

## 三、怎么用

用对话的方式说就行，不需要记命令。

### 场景 1：把一份现有文档排成标准公文（最常用）

> 用公文格式排版 `/Users/xxx/关于学校6处国有资产房屋出租的请示.docx`，输出到同目录

它会：
1. 读原文，自动识别标题、编号、表格、页码
2. 逐段判断是标题还是编号正文（拿不准的会列出来问你）
3. 按国标重排，生成新文件（**原文件不会被改动**）

### 场景 2：从一段文字新建公文

> 把下面这段文字排成一份请示，主送机关"XX省教育厅"，署名"XX师范大学"，成文日期"2026年3月17日"：
> （粘贴正文）

### 场景 3：只检查编号，不改文件

> 帮我检查这份公文的编号层级有没有错

会给出「段落位置 / 原文编号 / 问题 / 修正为」的表格，**征询后才改**，不擅自改动你的原意。

### 场景 4：指定页码

> 排版时页码居中显示
> 这份不要页码
> 按奇偶页不同排（双面打印装订）

不特别说明时，**以源文件为准**：源文件有页码就沿用它的样式，源文件没有就不加——单页文件、内部传阅件常常刻意不编页码，凭空加出来是越权，也不符合"一个字不增"。

### 场景 5：带表格的公文

> 把这份带附表的请示重排成标准格式，表格数据一个字都别改

表格会保留在原位置（正文引用处之后，或文末），横向、纵向合并的单元格原样重建。

### 场景 6：带红头的正式公文

> 这份文件有红头和文号，排版时红头保持原样，只重排正文

默认就是这样：红头、发文字号、红分隔线原样搬到新文档开头，从标题开始按国标重排。
**不用特别说明**——识别到版头会自动保留并告诉你保留了什么。

如果想**去掉**红头只留正文，明确说一声即可：

> 不要红头，从标题开始排

### 场景 7：排完再验一遍有没有漏东西

> 排完之后帮我核对一下，有没有漏字、漏表、漏图

会自动做这些检查：

1. **逐条核对原文（完整文字精确比对）**：源文档里的每一段文字（含表格每一格、页眉页脚），
   都要求**完整一致**地在成品里找得到。基准直接取自源文件，不经过中间结果——
   "提取时漏了、排版时也漏了"这种两头都漏的情况骗不过它。
2. **反向查少字/多字/替换**：成品里每一段也要和源文档**完整文字精确配对**。
   少字（截断成半句）、多字（加前缀）、替换（改否定词、改金额）都会报告原文位置、
   原文、成品和差异。默认不再用"互为子串"放行——「检测结果」不会因为包含在
   「检测结果不合格」里就被当成一致。
3. **表格按位置逐格比**：第几行第几列是什么，位置错了也算错。
4. **图片分部位计数**：正文、页眉页脚分别数。
5. **段落顺序**：识别未经允许的段落重排（内容都在、但顺序颠倒）。
6. **自动编号**：源文档带自动编号的段落，成品也必须保留编号，丢了判不通过。

另外单独查**页码**：源文件没有页码、成品却冒出页码，判为新增内容；
页码域缓存数字的变化不会误报成正文差异。

结果分**三类**，只有第一类才算成功：

| 结论 | 退出码 | 含义 |
|------|--------|------|
| 完全通过 | 0 | 内容没多没少、编号页码正常、无未处理内容 |
| 部分完成／待确认 | 1 | 有脚注/批注/图片等本技能不处理的内容，需你核对 |
| 不通过 | 2 | 有漏字、增字、替换、漏表漏图、编号丢失、段落重排 |

这是内容层面的检查，**不能证明版式正确**——版式还是要自己翻一遍页面。
想连页码位置一起验，可以再说一句：

> 顺便量一下页码位置对不对

需要本机装有 LibreOffice 才会做；装了会把成品转成 PDF 渲染后逐页量出
页码距版心下边缘多少毫米（国标要求 7mm），量不出来会直说，不会拿估算糊弄。

### 关于输出位置

**由你指定**。不指定就落在当前工作目录，不会自作主张存到桌面或某个固定文件夹。文件名也由你定。

**不会覆盖已存在的文件。** 指定的输出名如果已经存在，会自动另存为「原名_2.docx」并告诉你存到了哪，你手工改过的内容不会丢。想要别的行为可以直说：

> 覆盖原来那份，不用另存
> 碰到同名文件就停下问我

## 四、过程中会被问到什么

| 要素 | 什么时候问你 | 不提供会怎样 |
|------|------------|------------|
| 标题 | 从文本新建时必须 | 直接报错，不猜 |
| 主送机关 | 需要时 | 该要素不输出 |
| 正文 | 必须有 | —— |
| 附件名称 | 有附件时 | 不输出附件说明 |
| 发文机关署名 | 需要时 | 该要素不输出 |
| 成文日期 | 需要时 | 该要素不输出 |
| 输出路径 | 未指定时 | 落在当前目录 |
| 页码 | 无源文件可参照时 | 默认不加（要说要加才加），并在交付时说明 |

还有一类问题叫**存疑段落**：某个「1.」到底是三级标题，还是只是一条编号的工作事项？
这类判断它不会自作主张——**默认按正文处理（不加粗），并把疑问列成表请你拍板**。
原因是两种错误的代价不对称：漏加粗只是不够醒目，误加粗是整段变成视觉噪音。

## 五、排出来是什么样

| 元素 | 字体 | 字号 | 行距 |
|------|------|------|------|
| 标题 | 方正小标宋简体 | 二号 22 磅 | 32 磅 |
| 主送机关 | 仿宋_GB2312 | 三号 16 磅 | 28 磅 |
| 正文 | 仿宋_GB2312 | 三号 16 磅 | 28 磅 |
| 第一层 `一、` | 黑体 | 三号 | 28 磅 |
| 第二层 `（一）` | 楷体_GB2312 | 三号 | 28 磅 |
| 三/四/五层 | 仿宋_GB2312 加粗 | 三号 | 28 磅 |
| 页码 | 宋体 | 四号 14 磅 | 源文件有页码才排；源文档没有就不加 |

页面 A4：上 37mm、下 35mm、左 28mm、右 26mm，版心 156mm × 225mm，正文每自然段首行缩进 2 字符。

第三层及以下「加粗」、第五层「①」为实务通行做法，非国标强制。国标只规定到第四层。

## 五之附：排版要多久

普通篇幅的文档，从你给出文件到拿到成品，通常是**几十秒**；几十段、几十页的也一样，
耗时和页数基本不成正比。真正让时间变长的，是下面这几件事，不是篇幅：

| 情形 | 对耗时的影响 |
|------|------------|
| 只排版 + 内容验收 | 几十秒搞定，这是常态 |
| 额外「量一下页码位置」（版式实测） | 明显变慢——要把成品转成 PDF 渲染后逐页测量，是最耗时的一步 |
| 带版记 / 带落款日期 | 各多一轮转 PDF 校准，比纯排版略慢 |
| 要「把自动编号转成文字」 | 多一步解析并复制 Word 编号定义，几乎不影响体感 |
| 结构很乱、编号混用 | 我会多列几个存疑段落问你，等待你拍板的时间比脚本本身还长 |

**一句话**：如果你只是想把文档排成标准格式，很快；只有在额外要求"验证页码位置、验证落款对齐"这类**逐页实测**时，才会明显多花时间。这些实测都不是必须的——内容层面的验收（有没有漏字、漏表、漏图）在排版时已经自动做过了。

## 六、常见问题

**Q：字体被替换了，还合规吗？**
合规。替换只影响字形，字号、行距、缩进、页边距完全不变。想完全一致，装上国标字体重排一次即可。

**Q：为什么有的「1.」加了粗，有的没加？**
那是段落角色不同。作为**标题**的「1.」加粗，作为**编号的工作事项**（如「1. 完成了……」）不加粗。判断由 AI 结合上下文、是否成句、Word 大纲级别来做，不靠字数、不靠编号硬套。

**Q：编号会不会漏、重复或算错层级？**

自动编号（多级列表）会从 Word 的编号定义里算回来，下面这些情况都实测过：

- 每进入新的一级标题，下级从头计数（「2.」之后是「2.1.」，不会接着数成「2.3.」）
- 中间隔了不参与编号的段落，后面接着编
- 编号规则挂在段落样式上（段落本身看不出编号）
- 从指定数字开始（如从 5 开始）

**唯一会提醒你的是"手打编号和自动编号混用"**：两套各算一套，可能出现两个「一、」。
这种情况只提示不自动改——既可能是原文就写错了，也可能本来就是两套并行，自动改反而会乱层级。

**Q：源文件明明有「二、」，成品里怎么没有？**
那是 Word 自动编号：不是段落文字，挂在 `w:numPr` 上，显示出来但不存在于字符里。
本技能会把源文档的编号定义原样复制进成品、给段落带上编号定位，**由 Word 自己渲染
出「一、」「1.」等序号**——所以成品里依然看得到编号，只是它不被写进正文字符。
如果发现编号真的没了，多半是打开成品的环境没加载编号定义；想要它变成普通文字
（以后不随列表自动更新），说一句"把自动编号转成文字"即可。

**Q：表格数据会不会被改？**
不会，逐格照搬。合并单元格会按 `gridSpan`/`vMerge` 原样重建——如果处理不当，一个跨 2 列的「300」会被复制成两个 300，等于凭空造数。

**Q：落款会排两遍吗？**
不会。源文档的署名与成文日期会被标成落款元素，**留在源文档原来的位置**输出——通知类公文
的落款本来就在正文之后、附件之前，挪到文末会让成文日期掉到最后一页。主送机关和附件说明
因为误判代价高，只列为候选请你确认，不会自动删除。

**Q：成文日期为什么是居中的，不是国标说的"右空四字"？**
本技能按**成文日期的中心对准发文机关署名的中心**排。国标 7.3.5 的字面写法是署名右空二字、
日期右空四字，两条各自右对齐，结果两条字的中心并不重合，盖章时压不正。居中排更好盖章，
也是公文实务里更常见的做法。排完会实测两条文字的中心线，偏差通常 0.00mm。
想改回国标字面口径，说一句就行（实现上把 `sign_date_indents()` 的返回值换成固定两字/四字）。

**Q：版记（印发机关和印发日期）会被重排吗？**
不会。源文件有版记时，它整块**原样搬到文末**——字号、印发机关与印发日期之间的间隔、
上下两条分隔线都不动，只把它沉到**最后一页版心最下方**（国标 7.4.2 要求版记最后一个
要素在最后一行）。之所以不重排：版记是各单位自己排好的，重排一次就变一次样。
源文件没有版记就不生成，不会替你编抄送机关。

**Q：万一它把不是落款的段落当成落款剥掉了呢？**
有可能，所以**每条剥离都会给出判定依据**（例如"整段仅为 YYYY年M月D日""位于成文日期之上最近的非空短段"）、原段落序号、前后段落内容，并请你核对。
格式特殊的文档（名单式、表格化落款）可能判错，此时可以直说"不要自动剥离署名和日期"，两段会原样留在正文里由你自己处理。

**Q：原文件会被改吗？**
不会。始终生成新文件，原文件原样保留。

**Q：我手工改过的产出物，再排一次会不会被覆盖？**
不会。输出名已存在时默认自动另存为「原名_2.docx」并提示存到了哪，原文件一字不动；只有你明确说"覆盖原来那份"时才会覆盖。
这是有意为之——排版产出常被人工补内容、调措辞，覆盖不可撤销，宁可多出一个文件。

**Q：能批量排吗？**
可以，一次给多个文件路径。每份都会单独确认要素。

**Q：红头是图片，能保留吗？**
能。图片版红头和文字红头一样会原样复制，图片本身也会一并带过去，不会变成空白或报文档损坏。

**Q：为什么红头和正文看起来不是同一种字体？**

两个原因，都不算排版错误：

1. **本机没装红头用的字体**（最常见）。国标标题字「方正小标宋简体」是 Windows 上的
   商业字体，macOS 一般没有。正文缺字体时本技能会**回退到本机等效字体**
   （如「宋体-简」）；红头按"原样保留"原则**不做回退**，保留原字体名由 Word 自行替换。
   两套策略不同，就会出现红头和正文不同字体。输出时会提示缺哪个字体。
2. **红头本身没逐字设字体**，用的是源文档的文档默认字体。本技能会把源文档的默认字体
   一起带过来，所以红头应当与源文件里显示一致；若仍不一致，多半是上一条的字体缺失。

想让两者统一，在源文件中把红头改成你本机已有的字体（如「宋体-简」「华文中宋」），
或安装对应字体后再排。

**Q：版头识别错了怎么办？**
提取结果里有 `_head_detail`，会写明每段为什么被判成版头。确认后可手工调整：
要保留就改 `header.indices`，不要红头就把 `header` 整段删掉。
识别本身是保守的——只扫描开头连续几段，正文里引述「X教发〔2026〕15号」不会被误删。

**Q：正文里有图片、脚注、修订标记，会怎么样？**
会明确提示你，不会一声不响地漏掉。提取时会扫描正文中的图片、文本框、脚注、尾注、
批注、修订标记、嵌入对象、公式，列出各有几处、在第几段，并说明本技能不保留它们。
**正文图片不参与重排**，需要你自己补回去；版头里的图片不受影响，会正常复制。

**Q：多个附件会排在一起吗？**
不会。每个附件单独一段。名称太长需要回行时，回行会与附件名称首字对齐（国标 7.3.4），
序号也与第一个附件的序号对齐，不会参差不齐。

**Q：排完之后怎么知道内容有没有变？**
说一句"核对一下有没有漏字、漏表、漏图"，会做这些检查：逐条核对源文档里的每一段文字
（含表格每一格、页眉页脚，基准直接取自源文件，不经过中间结果）、**反向按完整文字精确
比对查少字/多字/替换**、表格按第几行第几列逐格比对、图片按正文与页眉页脚分别计数、
段落顺序、自动编号，并单独查源文件没有页码时成品是否冒出了页码。
结果分「完全通过（0）／部分完成（1）／不通过（2）」三档，只有 0 才算成功。
报告中还会说明**有意调整的部分**（版头复制、转为文字的自动编号等），这些不是缺陷。
注意：这道检查只能证明内容没多没少，**不能证明版式正确**，版式仍需自己翻一遍页面。

**Q：页码位置能验吗？**
能，但需要本机装有 LibreOffice。说一句"量一下页码位置"，会把成品转成 PDF 渲染后
逐页量出页码一字线距版心下边缘多少毫米（国标要求 7mm），并给出每页的偏差。
**量不出来会直说，不会用估算糊弄你**——早期版本按估算设置，实际偏了 19mm。

**Q：原来的"标题与下段同页""段前分页"还在吗？**
在。「与下段同页」「段中不分页」「段前分页」这三个分页设置会跟着源文档走，
标题不会掉在页末。**手动分页符**（按 Ctrl+Enter 敲出来的那种）不保留，需要手工补。

## 七、进阶用法（维护者 / 命令行）

日常使用不需要看这一节。

```bash
pip install python-docx

# 推荐流程：提取 → 定角色 → 渲染
python3 scripts/inspect_docx.py 原文.docx -o content.json
# 审阅 content.json 的 _uncertain 存疑清单，定稿 type
python3 scripts/generate_gongwen.py --config content.json --output 公文.docx

# 纯文本正文（每行一段）
python3 scripts/generate_gongwen.py --title "关于XXX的请示" --recipient "XX厅" \
    --body-file body.txt --signature "XXX办公室" --date "2026年3月17日" --output 公文.docx

# 字体自检
python3 scripts/generate_gongwen.py --check-fonts

# 输出文件已存在时的处理（默认 rename）
python3 scripts/generate_gongwen.py --config content.json --output 公文.docx \
    --on-exist fail        # 碰到同名文件就停止（退出码 2）
python3 scripts/generate_gongwen.py --config content.json --output 公文.docx \
    --on-exist overwrite   # 明确覆盖同名文件

# 版式实测：页码位置（需 LibreOffice + pip install pymupdf）
python3 scripts/measure_page_number.py 公文.docx
python3 scripts/measure_page_number.py 公文.docx --json result.json --tolerance 0.5

# 内容验收（默认 strict：完整文字精确比对，少字/多字/替换判不通过）
python3 scripts/verify_output.py 原文.docx 公文.docx content.json
python3 scripts/verify_output.py 原文.docx 公文.docx content.json --fidelity standard

# 把 Word 自动编号固化成纯文字（默认 strict 保留原生编号）
python3 scripts/inspect_docx.py 原文.docx -o content.json --fidelity standard
```

**验收脚本退出码**（`verify_output.py`）：`0` 完全通过；`1` 部分完成／待确认（有脚注/批注/图片等不处理内容）；`2` 不通过（内容丢失、增字、替换、漏表漏图、编号丢失、段落重排）。

**生成器退出码**（`generate_gongwen.py`）：`0` 成功；`1` 参数/内容错误；`2` 输出文件已存在且策略为 `fail`；`3` 无法写入（文件正被 Word/WPS 打开或无权限）。

`content.json` 结构（角色必须显式指定）：

```json
{
  "title": "关于XXX的请示",
  "recipient": "XX厅",
  "body": [
    {"type": "body", "text": "总起段落……"},
    {"type": "heading1", "text": "一、第一层标题"},
    {"type": "heading2", "text": "（一）第二层标题"},
    {"type": "numbered_body", "text": "1. 完成了……，开展了……。"},
    {"type": "table", "index": 0},
    {"type": "blank", "text": ""}
  ],
  "tables": [{"rows": [["列1", "列2"], ["值1", "值2"]], "header": true}],
  "attachments": ["附件名称"],
  "signature": "发文机关署名",
  "date": "2026年3月17日",
  "page_number": "center",
  "on_exist": "rename",
  "output": "公文.docx"
}
```

`type` 取值：`heading1`~`heading5`、`body`、`numbered_body`、`attachment_title`、`blank`、`table`。

`attachment_title` 是附件另页起排时那一行标题（二号小标宋居中）。印发类通知后面常跟着
附件全文，它开头的标题就该用这个角色。

纯字符串（不写 `type`）时按保守策略兜底：`一、`/`（一）` 判为标题，`1.`/`（1）`/`①` 一律按编号正文（不加粗）。

也可作为模块调用：

```python
from scripts.generate_gongwen import build_document

build_document(content_dict, '公文.docx')                        # 同名则自动另存 _2
build_document(content_dict, '公文.docx', on_exist='overwrite')  # 明确覆盖
```

`on_exist`：`rename`（默认，自动另存）/ `fail`（抛 `FileExistsError`）/ `overwrite`（覆盖）。
返回值是**实际写入的路径**——重名另存时与原传入值不同，交付给用户前务必用返回值。

## 打包发布（维护者）

技能包体积上限为 3MB。**打包前必须排除 `.git`**——官方 `package_skill.py`
不会自动排除，若直接在 git 仓库目录上执行，会把整个 `.git` 打进包里
（本仓库 `.git` 约 8MB，直接超限）：

```bash
# 推荐：手工打包并排除版本库、缓存、测试中间文件
zip -qr official-doc.zip official-doc \
    -x "*.git*" "*.DS_Store" "*__pycache__*" "*/outputs/*" \
       "*/tests/*.docx" "*/tests/*.pdf" "*/tests/*.json"
```

打完按 `official-doc.zip` 命名（与技能目录同名），并确认包内结构为
`official-doc/SKILL.md`、`official-doc/scripts/`、`official-doc/references/`、
`official-doc/tests/run_regression.py`。包内不得含真实合同、个人资料、缓存、
测试输出或密钥。
