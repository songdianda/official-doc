# 党政机关公文格式规范（GB/T 9704-2012）

依据《党政机关公文格式》GB/T 9704-2012 及《党政机关公文处理工作条例》（中办发〔2012〕14号）。

## 0 字体说明（重要）

公文排版依赖以下字体，本技能包**不附带字体文件**（字体受著作权保护，需用户自行取得）：

| 用途 | 推荐字体 | 说明 |
|------|---------|------|
| 标题 | 方正小标宋简体 / 小标宋体 | 国标要求「2号小标宋体字」 |
| 正文、主送机关、附件说明 | 仿宋_GB2312 或 仿宋 | 国标要求「3号仿宋体字」 |
| 第二层标题 | 楷体_GB2312 或 楷体 | 国标要求「楷体字」 |
| 第一层标题 | 黑体 | 国标要求「黑体字」 |
| 页码 | 宋体 | 国标要求「4号半角宋体」 |

**python-docx 只能设置字体名称，不能嵌入字体文件。** 生成脚本内置字体回退链，会按「国标名 → 等效字体 → 通用兜底」逐项匹配本机已装字体，避免 Word 静默替换为默认字体。各系统实际字体名并不一致：

| 用途 | Windows 常见 | macOS 常见 | Linux 常见 |
|------|------------|-----------|-----------|
| 标题 | 方正小标宋简体 | （通常无小标宋，退到宋体类中宋） | 无，退到宋体 |
| 正文 | 仿宋_GB2312 / 仿宋 | 方正仿宋_GBK / 华文仿宋 | FangSong |
| 第二层 | 楷体_GB2312 / 楷体 | 楷体-简 / 华文楷体 | Kai |
| 第一层 | 黑体 | 黑体-简 / 华文黑体 | Hei / SimHei |
| 页码 | 宋体 | 宋体 / 宋体-简 | SimSun / Songti SC |

**注意**：字体缺失不会改变字号、行距、缩进、页边距等参数，但会改变字的外形。若标题被回退到普通宋体，仅影响观感，不影响合规性判定。

Windows 一般自带仿宋、楷体、黑体、宋体；「仿宋_GB2312」「楷体_GB2312」「方正小标宋简体」多数需单独安装（方正字体为商业字体，商用需取得授权）。

## 1 页面设置

| 项目 | 值 | 依据 |
|------|-----|------|
| 纸张 | A4 210mm × 297mm | 5.1 |
| 上白边（天头） | 37mm ± 1mm | 5.2.1 |
| 左白边（订口） | 28mm ± 1mm | 5.2.1 |
| 版心尺寸 | 156mm × 225mm | 5.2.1 |
| 下白边 | 35mm（由 297 − 37 − 225 推算） | 推算值 |
| 右白边 | 26mm（由 210 − 28 − 156 推算） | 推算值 |
| 每面行数 | 22 行 × 每行 28 字 | 5.2.3 |

## 2 标题

- 字体：**小标宋体（方正小标宋简体）**，字号 **二号（22磅）**
- 对齐：居中，可分一行或多行
- 行距：固定值 32 磅，段前段后 0
- 组成：「发文单位 + 关于 + 事由 + 文种」
- 回行要求：词意完整、排列对称、长短适宜、间距恰当；排列应为**梯形或菱形**，不得为上下等长的长方形或上下长中间短的沙漏形（7.3.1）

## 3 主送机关

- 编排于标题下空一行，**居左顶格**，回行仍顶格
- 最后一个机关名称后标**全角冒号**
- 字体：**仿宋_GB2312**，三号（16磅），行距固定值 28 磅
- 主送机关过多导致首页不能显示正文时，移至版记（7.3.2）

## 4 正文

- 字体：**仿宋_GB2312**，三号（16磅）
- **每个自然段左空二字**（首行缩进 2 字符），回行顶格
- 行距：固定值 28 磅，段前段后 0
- 公文首页必须显示正文（7.3.3）

### 4.1 结构层次序数

国标原文（7.3.3）：层次序数依次可用「一、」「（一）」「1.」「（1）」标注；**第一层用黑体字、第二层用楷体字、第三层和第四层用仿宋体字**。

实务中常用到第五层。本技能采用的字体规则：

| 层级 | 编号格式 | 字体 | 加粗 | 说明 |
|------|---------|------|------|------|
| 第一层 | `一、` | 黑体 | 否 | 国标明确 |
| 第二层 | `（一）` | 楷体_GB2312 | 否 | 国标明确 |
| 第三层 | `1.` | 仿宋_GB2312 | 是 | 国标未要求加粗，**加粗为通行做法** |
| 第四层 | `（1）` | 仿宋_GB2312 | 是 | 同上 |
| 第五层 | `①` | 仿宋_GB2312 | 是 | 国标未列第五层，**为实务扩展** |

- 第一、二层标题一般末尾不加标点符号，单独成段、不接内容

### 4.2 编号正文（非标题）

带编号但内容是工作事项的段落（如工作总结中「1. 完成了……，开展了……」），
**按正文排版、不加粗**，角色记为 `numbered_body`。

判断与处理详见 `references/paragraph-roles.md`。要点：
- 编号前缀相同不代表角色相同，`1.` 可能是 `heading3` 也可能是 `numbered_body`
- 拿不准按 `numbered_body` 处理并列出疑问
- 不得改写、补全、重排编号

### 4.3 附表

国标未对附表字号作强制规定。本技能采用的通行规格：

| 项目 | 值 |
|------|-----|
| 对齐 | 表格整体居中 |
| 边框 | 全线边框（`Table Grid`） |
| 字体 | 随正文用仿宋 |
| 表头字号 | 小四（12磅），**加粗** |
| 数据字号 | 五号（10.5磅） |
| 单元格 | 水平居中 + 垂直居中 |

- 附表数据必须与原文逐格一致，**不得改动任何数值**
- 位置：正文引用处之后，或文末（落款之后）
- 正文若已写明「（详见附表）」，可不再另加「附件：」说明
- **合并单元格**：源表的横向（`w:gridSpan`）与纵向（`w:vMerge`）合并会被解析并原样重建。
  提取时必须按合并信息处理，否则一个跨 2 列的「300」会被读成 `['300','300']`，
  等于凭空造出一个不存在的数值——这与"逐格一致"直接冲突

## 5 附件说明

- 正文下空一行，**左空二字**编排「附件」二字
- 后标**全角冒号**和附件名称；多个附件用阿拉伯数字标注顺序号（如「附件：1. XXXXX」）
- 附件名称后**不加标点符号**
- 名称较长需回行时，与上一行附件名称**首字对齐**（7.3.4）

### 5.1 实现要点

- **多个附件逐条单独成段**。拼在同一段里，长名称就无法按首字对齐，
  续行会掉到下一行行首。
- 用**悬挂缩进**实现回行对齐，注意 OOXML 语义与直觉相反：
  `w:left` 是**续行**的左边界，`w:hanging` 是首行相对续行**向左突出**的量。
  要让首行在 S 字处、回行在 C 字处，应取 `left=C`、`hanging=C-S`。
  误写成 `left=S`、`hanging=C-S` 会让首行跑到版心外面（实测左溢 14mm）。
- 缩进按**磅值**写入，不要用字符值——字符值会被文档默认字号带偏，见第 9 节。

各附件的取值（单位：三号字字符，1 字 = 16pt = 5.64mm）：

| 情形 | 首行位置 S | 回行位置 C | left | hanging |
|------|-----------|-----------|------|---------|
| 单个附件 | 2（左空二字） | 5（名称首字） | 5 | 3 |
| 多个附件第 1 条 | 2 | 6.5 | 6.5 | 4.5 |
| 多个附件第 2 条起 | 5（与首个序号对齐） | 6.5 | 6.5 | 1.5 |

「1. 」为半角数字+点+空格，宽约 1.5 个三号汉字，故取 1.5。

## 6 发文机关署名与成文日期

- 正文（或附件说明）下空一行，**右空二字**编排发文机关署名
- 署名下一行编排成文日期，首字比署名首字**右移二字**
- 成文日期用阿拉伯数字将年、月、日标全，月、日不编虚位（7.3.5.2 / 7.3.5.4）
- 字体：仿宋_GB2312，三号（16磅），行距固定值 28 磅

## 7 页码

国标原文（7.5）：**4号半角宋体**阿拉伯数字，编排在版心下边缘之下，数字左右各放一条一字线；**一字线上距版心下边缘 7mm**。单页码居右空一字，双页码居左空一字。

| 项目 | 值 |
|------|-----|
| 字体 / 字号 | 宋体 / 四号（14磅） |
| 格式 | `— 1 —`（左右各一条一字线） |
| 一字线上沿距版心下边缘 | **7mm**（国标原文口径） |
| `section.footer_distance` | **23.58mm**（实测校准值，见下） |

> **23.58mm 是怎么来的**（此前按"叠加字号半高"估算成 4.58mm，实测是错的）：
> 生成 7 页样本 → LibreOffice 转 PDF → 按 300dpi 渲染扫描墨迹，量出一字线上沿
> 相对版心下边缘的距离。`footer_distance = 4.58mm` 时实测 **26.00mm**（偏差 +19.00mm，
> 页码几乎贴着页底），补上 19.00mm 后取 23.58mm，复测 **7.03mm**（偏差 0.04mm）。
> 版心下边缘距页底 35mm，故页码落在距页底约 28mm 处。

### 7.0 成品实测记录（不是样本估算）

页脚距页底设多少，不等于页码落在哪里。用真实内容生成的**成品**逐页复测（`scripts/measure_page_number.py`）：

| 成品 | 页数 | 距版心下边缘 | 与 7mm 偏差 | 水平位置 |
|------|------|------------|-----------|---------|
| 9 页成品，`center` | 9 | 6.99–7.07mm | −0.01 ~ +0.07mm | 中心 106.04mm（版心中心 106mm，偏差 +0.04mm） |
| 9 页成品，`odd_even` | 9 | 6.99–7.07mm | −0.01 ~ +0.07mm | 单页右空 5.52mm、双页左空 5.70mm（一字 5.64mm） |

复测方法：成品 → LibreOffice 转 PDF → 300dpi 渲染 → 在页脚区域扫描非白像素，
取第一行墨迹的上沿换算毫米。墨迹比文字 bbox 更贴近视觉位置（bbox 上沿约高 0.8mm）。

一键复测：`python3 scripts/measure_page_number.py 成品.docx`（需 LibreOffice + `pip install pymupdf`）。
量不出来会明确报错退出，**不会用估算代替实测**。

### 7.1 三种页码样式（可选）

`page_number` 配置项控制页码样式：

| 取值 | 效果 | 适用场景 |
|------|------|---------|
| `center` | 所有页页码**居中**，不区分奇偶页 | 单面打印、单位内行文、呈报稿 |
| `odd_even` | 单页码居右空一字、双页码居左空一字 | 双面打印并装订成册，严格按 7.5 执行 |
| `none` | **不显示页码** | 源文档本就没有页码 |

**判定原则：源文档没有页码，就不要替它加。** 排版是重排格式，不是替用户决定要不要页码——单页文件、内部传阅件常刻意不编页码，凭空加出来是越权。`scripts/inspect_docx.py` 会自动检测源文档页码并写入 `page_number`（无→`none`，有→沿用原样式）；纯文本新建时默认 `center`。

为什么不默认奇偶页：7.5 的左右错位是为**双面装订**设计的——翻开书时页码靠外侧才好看。单面打印或仅电子传阅时，页码忽左忽右反而显得凌乱；多数单位的日常行文、呈批件也并不按装订本排版。

- 版记页前有空白页的，空白页和版记页不编排页码
- 附件与正文一起装订时，页码连续编排
- 选 `odd_even` 时若只取到单页页脚，脚本会降级为仅奇数页显示并保留页码

## 8 版头（红头 / 发文字号 / 分隔线）

国标 7.2 的版头要素：发文机关标志（红头）、发文字号、签发人、分隔线等。

**本技能不重做版头，只原样保留。** 红头是各单位的门面，替用户重排等于改他的门面。

### 8.1 识别规则

只扫描文档**开头连续**的那几段（最多前 6 段，遇到第一个不像版头的段落即停止）。
正文里引述「X教发〔2026〕15号」不会被误当成版头删掉。

打分判定，累计 ≥ 2 分即纳入：

| 特征 | 分值 |
|------|------|
| 红色文字（R ≥ A0，G/B ≤ 60） | 2 |
| 字号 ≥ 二号（22 磅） | 1 |
| 符合发文字号格式 | 3 |
| 以「文件」结尾（限前 3 段） | 2 |
| 文本框内文字（限前 3 段） | 1 |

**文本框（`w:txbxContent`）**：框内的 `w:t` 不在段落的直接 `w:r` 下，`p.text` 读不到，
脚本单独取出参与打分，并作为该段的显示文本写入 `header.texts`（否则那段看起来是空的）。

无文字的段落：带 `w:pBdr`（红色分隔线）或含图片（图片版红头）直接纳入。
识别到发文字号之后只再接受分隔线，防止正文标题被误纳入。

### 8.2 不支持：表格式版头

用表格排的红头（机关名与文号各占一格）**不会**被识别为版头。
本技能只扫描段落，表格会作为普通表格排在标题之后，位置与源文件不同。

此时 `scripts/inspect_docx.py` 会在 `_warnings` 中提示「文档以表格开头」，
**不静默处理**——交付时必须转告用户，由用户决定是改源文件还是手工调整。

### 8.2 保留方式

整段 `deepcopy` 源 `w:p` 到新文档开头，字体、颜色、字号、对齐、边框一概照搬。
图片（`w:drawing` / `w:pict`）必须重建关系 ID——直接复制 XML 会让 `r:embed`
指向源文档的图片部件，在新文档里是悬空引用，轻则图片空白、重则提示文档损坏。

### 8.3 源文件没有版头

不凭空生成。需要红头时在单位红头模板上套打。

## 9 缩进单位：用磅值，不要用字符值

`w:ind` 同时支持字符值（`firstLineChars` / `leftChars` / `hangingChars` /
`rightChars`）与绝对值（`firstLine` / `left` / `hanging` / `right`，单位 twips）。

**字符值的实际宽度由文档默认字号决定，不是当前段落字号。** python-docx 新建
文档的默认字号是 11pt，用它排三号字（16pt）的公文时：

| 想达到的效果 | 按三号字算 | 写 `firstLineChars=200` 实测 |
|-------------|-----------|---------------------------|
| 首行缩进 2 字符 | 11.3mm | **7.8mm**（按 11pt 折算，少 3.5mm） |

同一段文字，两种写法的成品相差近三分之一字符宽，肉眼能看出来。

因此本技能**只写绝对值**（`set_indent_pt`，按 `SIZE_BODY` 折算成 twips），
不写字符值。副作用是 Word 缩进对话框里显示的是毫米数而非"2 字符"，
但成品位置是准的——位置准比显示好看重要。

同理适用于：正文首行缩进、附件说明左空二字与悬挂、署名右空二字、
成文日期右空四字、页码居右/居左空一字。

## 10 分页控制：随源文档保留

国标不管分页细节，但排版不能把作者的分页意图弄丢。Word「段落 → 换行和分页」
里的三个开关写在 `w:pPr` 上，本技能**照搬，不自作主张**：

| 属性 | Word 里的名字 | 丢了会怎样 |
|------|-------------|-----------|
| `w:keepNext` | 与下段同页 | 标题孤零零留在页末，正文翻到下一页 |
| `w:keepLines` | 段中不分页 | 一段文字被切成两页 |
| `w:pageBreakBefore` | 段前分页 | 本该另起一页的内容接在上一页尾部 |

`scripts/inspect_docx.py` 读到源段落有这些设置时，写进 body 元素的
`keep_next` / `keep_lines` / `page_break_before`（值为 `true`）；
没设就不写。标题的「与下段同页」单独记为 `title_keep_next`。
生成器按同一段落写回对应属性。

schema 顺序：`w:keepNext` / `w:keepLines` / `w:pageBreakBefore` 必须排在
`w:numPr`、`w:spacing`、`w:ind`、`w:jc` **之前**，否则严格的解析器会判不合规。

**不保留**：手动分页符（run 里的 `w:br type="page"`，即 Ctrl+Enter 敲出来的那种）。
分页符不是段落属性，需手工补。
