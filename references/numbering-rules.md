# 公文结构层次编号检查规则

## 1 层级格式对照

| 层级 | 唯一合法格式 | 常见错误写法 |
|------|-------------|-------------|
| 第一层 | `一、` `二、` `三、` | `1.` `（一）` `第一,` |
| 第二层 | `（一）` `（二）` `（三）` | `1、` `1.` `(1)` `（1）` `A.` |
| 第三层 | `1.` `2.` `3.` | `1、` `1）` `（1）` `①` |
| 第四层 | `（1）` `（2）` `（3）` | `1)` `(1)` `①` `a.` |
| 第五层 | `①` `②` `③` | `a.` `A)` |

## 2 检查要点

1. **层级格式必须严格对应**，不得跨层使用编号。
2. **层级嵌套必须连续**：第一层下必须是第二层，不能跳到第三层或第四层。
   - 错误：「一、」下直接出现「1.」，应为「（一）」
   - 错误：「一、」下直接出现「（1）」，应为「（一）」
3. **同一父级下的同层编号必须连续且格式统一**。
   - 正确：（一）（二）（三）
   - 错误：（一）（三）—— 跳号
   - 错误：（1）、2、3、—— 同层格式不一致
4. **顿号「、」不得用于数字编号**：`1、` 应改为 `1.`。顿号仅用于第一层汉字编号后（如「一、」）。
5. **括号必须使用全角中文括号**：`(1)` 应改为 `（1）`；`(一)` 应改为 `（一）`。
6. **同一份文档里混用「手打编号」与「Word 自动编号」是最常见的事故源**，见下节。

## 2.1 Word 自动编号（必读，容易整条丢失）

Word 的自动编号**不是段落文字**，它挂在 `w:pPr/w:numPr` 上，渲染时由 `numbering.xml` 生成。
python-docx 的 `p.text` 只取 `w:t`，**取不到自动编号**——直接提取会让编号整条消失。

典型现场（真实案例）：

```
一、请示内容     ← 手打的文字，p.text 能取到
二、请示依据     ← Word 自动编号（numId=2, ilvl=0, start=2），p.text 只有「请示依据」
```

结果是「一、」在、「二、」没了，看起来像"少了一级"。

**处理办法**：`scripts/inspect_docx.py` 会自动解析 `numbering.xml`，算出每段应显示的编号并补回文本：

- 解析 `numId → abstractNumId → (numFmt, lvlText, start)`，支持 `startOverride`
- 按 `(numId, ilvl)` 分组计数，序号 = `start + 出现次序 - 1`
- 支持 `japaneseCounting`（一 二 三）、`decimal`、`lowerLetter`、`upperLetter`、`lowerRoman`、`upperRoman`
- 项目符号（`bullet` / `none`）保留符号本身
- 补回的编号记在 `_src.autoNumber` 与 `_auto_number` 里，**审阅时能看到哪些是自动生成的**

注意两点：

1. 补回的编号**在源文件里不是字符**，只是还原 Word 的显示效果。若用户其实不想要那个编号，删掉即可——但**默认应还原**，否则等于丢内容。
2. 自动编号混着手打编号时，两者格式可能不一致（如手打「一、」、自动生成「二.」）。检查时要按**显示效果**核对，不能只看 `p.text`。

### 2.2 多级列表的四种复杂情况

Word 的"多级列表"不止是单级计数，下列情况均已实测：

| 情况 | Word 的实际行为 | 本技能的处理 |
|------|----------------|-------------|
| **每进入新章节，下级从头计数** | 一级从 1 变 2 后，其下的二级从 1 重新开始 | 本级计数推进时，把所有**更深层级**的计数重置为各自 `start`。不重置的话第二章的二级会接着数成「2.3.」 |
| **中间暂停编号，后面接着编** | 中间插入普通段落不影响计数 | 计数按 `(numId, ilvl)` 持久保存，普通段落不参与 → 正确续编 |
| **手打编号与自动编号混用** | 两套各算一套 | 补回后检测同级重复，写入 `_number_conflicts`。**只报告不自动改**——重复可能是原文就错，也可能是两套并行，改错会乱层级 |
| **编号规则来自段落样式** | 段落自身没有 `numPr`，规则挂在样式上 | 解析 `styles.xml`，沿 `basedOn` 继承链向上找到第一个带 `numPr` 的样式。只看段落自身会**整条丢失** |

实现要点：

- `numPr` 的查找顺序：**段落自身 `pPr` → 段落样式（含继承链）**。段落自身的优先。
- 计数重置只作用于**同一 `numId` 内、层级更深**的键；跨 `numId` 互不影响。
- 重复检测要排除多级编号误判：`1.` 与 `1.1.` 都以 1 开头，正则用 `^(\d+)[.、](?!\d)` 排除，否则会误报一堆冲突。

## 3 报告格式

检查完成后，以表格形式向用户报告：

```
发现以下编号问题：

| 段落位置 | 原文编号 | 问题说明 | 修正为 |
|---------|---------|---------|--------|
| 第X段   | 1、     | 第二层应使用（一）格式 | （一） |
```

如无编号错误，输出「编号检查通过，未发现问题。」
